# 活动课专项PRD优化开发文档

版本：V1.0  
日期：2026年10月26日  
适用对象：业务负责人、产品、设计、前后端开发、测试

## 1 改造目标与范围

活动课需要同时支持家长自主报名、运营筛选推送、校区招生跟进和多课节教学。此次改造建立独立的“活动课”业务入口，并复用已有课程、教室、线索、订单和拼团能力，让一次报名在各部门之间持续流转，课程、校区、时间及交易信息始终可追溯。

核心流程是：家长选择课程与上课安排，报名先进入运营的活动报名列表；运营勾选后主动推送，系统按所选校区归集，由校区主管分配顾问。招生按对应教学班级组织跟进，教师和教务按课节开展教学与考勤。

本文件是[部门协同总PRD](./教培CRM部门协同改造PRD.md)的活动课专项细化。活动课规则冲突时，以本文件第二章的最新确认结论为准；正价课、续报等非活动课规则仍沿用总PRD。

### 本次范围

- 活动课创建、校区与时间配置、教室关联、多课节安排。
- 直接售卖、固定人数规格拼团、虚拟成团、失败退款。
- 家长报名、缴费与名额校验。
- 活动报名总表、多选或全选、手动推送校区。
- 校区主管分配、按班级跟进、原顾问推荐、来源与结果回显。
- 课节考勤、报名变更与交接联动、岗位权限和操作记录。

“未成团但已经开课”的场景由业务明确排除，本次不为其增加分支，也不新增“拼团截止必须早于开课”的强制限制。免费活动的成交与占位规则不在本次低价售卖方案中另行扩展。

第二章为已确认业务规则。后续章节给出开发方案及验收要求；尚未确认的业务细节集中列于第十二章，不作为已确认制度直接上线。

## 2 已确认业务规则

| 编号 | 业务规则 | 产品约束 |
| --- | --- | --- |
| BR01 | 名称保持“活动课”，课程下可含一个或多个课节 | 不把活动课一级入口或商品名称改成“活动班” |
| BR02 | 家长选择的校区、时间是预先确定的安排 | 不按意向时间收集后再统一协调 |
| BR03 | 同一孩子一次报名同一门活动课，只选一个安排 | 校区与时间联动单选，不勾选多个替代时段 |
| BR04 | 活动课选择教室，沿用教室人数限制 | 不另设与教室容量脱离的活动人数上限 |
| BR05 | 未缴清不预留名额，缴费时重新检查 | 不采用提交订单即预留15分钟的方案 |
| BR06 | 缴清后即使未成团，也保留真实学生名额 | 成团等待不能释放已缴清学生的名额 |
| BR07 | 支持低价直接售卖与拼团售卖 | 课程和教学资料共用，售卖方式分别配置 |
| BR08 | 拼团家长各自报名、各自付款 | 不按一名家长统一代付全团设计主流程 |
| BR09 | 二人团、三人团等规格的价格事先确定 | 按选定规格下单，不因人数变化自动升档或改价 |
| BR10 | 团与班分开，不要求同校区或同场次参团 | 拼团不决定教学分班，团员各有自己的报名安排 |
| BR11 | 开启虚拟成团，活动到期或结束仍未满时补齐虚拟名额 | 保留原团规格和价格，不要求因人数不足补差价 |
| BR12 | 关闭虚拟成团，到期仍未满则取消并退款 | 退款按真实订单及实际已收金额处理 |
| BR13 | 报名先停留在活动报名列表 | 不因提交报名自动进入校区招生队列或新增招生跟进任务 |
| BR14 | 运营可多选或全选，主动点击“推送校区” | 按每条报名所选校区分发，不把整批强制送往同一校区 |
| BR15 | 未缴清、未成团的报名也允许被选中推送 | 缴费和成团状态不能成为该操作的统一前置条件 |
| BR16 | 校区主管指定具体招生顾问 | 推送不等于自动分配个人 |
| BR17 | 招生按对应班级组织沟通 | 支持班级分组，并直接展示所报课程、校区和时间 |
| BR18 | 同一孩子再次报名同校区活动课，优先推荐原顾问 | 仍由主管确认或调整，不自动跳过分配 |
| BR19 | 全部应缴费用交清才计缴清及相应成交结果 | 定金和部分付款不等于缴清；活动缴清也不等于正价转化成功 |

## 3 业务对象与关系

### 3.1 课程和教学安排

“活动课”是对外发布和报名的课程。一门活动课可以开放多个校区及时间安排，每份可报名安排关联实际教学班级和一个或多个课节。工作人员配置教室，家长选择已发布的课程、校区及时间安排，不需要自行选择教室。

家长选定一个多课节安排后，应能查看其完整课表；“单选”指在不同报名安排之间选一个，不是把课程内的多个课节拆成任选。

保留现有班级能力用于学生分组、教师教务分工和招生按班查看。它是活动课的教学组织关系，不新增名为“活动班”的一级产品入口。内部字段命名可以复用已有班级对象，页面仍使用“活动课”“课节”和原有班级名称。

### 3.2 报名与线索

活动报名记录是连接获客、交易、教学和招生的业务凭据。学生档案记录“是谁”，活动报名记录“这次报了什么”，招生任务记录“这次由谁跟进”。不得把所有活动的课程与时间写进学生档案的一个可覆盖字段。

未推送时，只形成活动报名及关联交易记录；即使学生已有线索档案，也不因本次报名自动新增招生任务或改变原顾问。运营执行推送后，创建或关联校区承接事项；主管分配后，进入顾问的活动招生待办。

同一学生报名不同课程时保留各自的报名与跟进上下文，学生基础档案复用。共用家长手机号不能作为自动合并两个孩子的唯一依据。

### 3.3 拼团与教学分开

一个团确定售卖规格及成团结果；每个真实团员关联自己的报名、订单、校区和教学安排。虚拟补位只增加拼团统计中的虚拟名额，不产生学生、订单、线索、教学名额或考勤记录。

例如，三人团的三名真实学生分别选择A校区周六、A校区周日、B校区周六的安排，各自只占所选安排的一个名额；不能把团人数整体计入其中某个教室。

## 4 页面结构与字段

### P01 活动课列表

入口建议放在运营的“活动课”模块。列表展示课程名称、售卖方式、开放校区、课节数量或安排概况、发布状态、报名记录数、已缴清数、已推送数及招生转化结果。

主要操作为新建、编辑、发布或结束售卖、查看报名列表、查看教学安排。人数和报名人次分别标注，不能用拼团人数替代真实报名数据。

### P02 活动课设置

| 区域 | 必要字段 | 交互与校验 |
| --- | --- | --- |
| 课程资料 | 名称、介绍、科目或适用年级、封面、运营负责人 | 复用课程基础资料，业务用途标记为活动课 |
| 教学安排 | 校区、对应班级、可报名安排、课节清单、教师及教务 | 多个校区可分别配置，课节包含开始与结束时间 |
| 教室与容量 | 所选教室、教室容量、当前占用及剩余名额 | 教室限定在所选校区，容量自动引用并只读展示 |
| 直接售卖 | 直接购买价格、售卖期间、适用教学安排 | 订单保存下单时价格，不随后续编辑回改 |
| 拼团售卖 | 人数规格、各规格价格、售卖期间、虚拟成团开关 | 同一团锁定一种规格；明确显示跨校区及时间可参团 |
| 发布入口 | 报名链接或二维码、来源渠道标识 | 入口关联当前活动课与有效售卖方案 |

活动课页面是运营完成发布的主要入口。复用营销模块的拼团配置与结算能力；如果保留营销中心发起拼团的入口，应选择已有活动课并维护同一份售卖方案，不能复制出另一套课程和价格。

### P03 活动报名列表

该页面保留混合校区、时间与学生的完整报名总表。支持按课程、校区、教学班级或安排、上课日期、售卖方式、缴费状态、拼团状态、推送状态和分配状态筛选。

| 字段组 | 展示字段 |
| --- | --- |
| 学生 | 学生姓名、家长、联系方式 |
| 报名内容 | 活动课、所选校区、班级或安排、上课时间、多课节展开入口 |
| 交易 | 直接购买或拼团、所选团规格、订单应缴、已收、缴费状态 |
| 拼团 | 团编号、真实成团人数、虚拟补位人数、团状态 |
| 名额 | 未占位、已占位或已释放；所选安排剩余名额 |
| 交接 | 未推送或已推送、接收校区、推送人及时间 |
| 分配 | 待分配或已分配、推荐原顾问、实际负责顾问 |
| 结果 | 到课情况、招生跟进阶段、正价转化结果 |

核心操作为勾选、多选、全选、查看详情、推送校区。建议默认“全选本页”，另提供“选择当前筛选结果全部记录”，清楚显示范围和数量。切换筛选条件时不得隐藏保留旧选择而不提示。

点击“推送校区”后，先展示本批记录数及各校区分布。成功后回显各校区推送数量，原报名仍留在本列表；已推送记录不能因再次提交重复生成承接事项。失败记录显示具体原因并可单独重试。

### P04 校区活动报名招生

该页面属于现有线索体系中的活动招生工作视图，不建立另一套独立学生或线索库。主管看到本校区已推送记录，默认按活动课及对应教学班级分组，可展开学生列表。

分组头展示活动课、校区、班级或安排、课表摘要、待分配数量和待首次联系数量。支持整组选择或部分学生选择后批量分配，最终责任仍记录到每条报名对应的招生任务。

同校区已有原顾问时，显示推荐人及推荐原因；主管确认后才完成分配。原顾问已停用或已无当前校区权限时，不得作为可分配对象，转为由主管重新选择。

顾问可以用同样的分组视图查看本人任务，分组计数也只统计本人有权查看的记录。

### P05 我的线索详情

详情顶部固定展示本次报名摘要：活动课、校区、班级或安排、完整课表入口、缴费状态、拼团规格及状态、名额状态、来源、当前顾问。

沟通记录关联本次活动报名，记录联系结果、家长需求、到课确认及下次联系时间。顾问在此可查看教学端回传的逐课节到课情况，并继续正价课转化。

同一学生存在多次报名时，提供报名切换或并列记录，不覆盖旧课程、旧时间与旧跟进历史。“转同事”保留为跟进责任交接入口；修改上课安排不能仅靠更换顾问完成。

### 配套页面复用

家长报名页采用课程、校区、时间安排联动单选，展示所选安排包含的课节及最终价格；进入拼团时锁定该团的规格，仍允许选择不同校区和时间安排。

教师与教务复用现有教学名单、课表和考勤页面，新增活动课筛选及报名关联。多课节课程按每一课节记录考勤，不用一条“已到课”覆盖整个课程。

## 5 功能需求与操作流程

### F01 创建活动课和教学安排

工作人员创建课程、配置一个或多个课节及各校区可报名安排，再选择直接售卖或拼团方案发布。家长看到的校区与时间必须来自已配置的有效安排，不允许提交任意自由文本替代。

容量引用教室限额。若同一批学生参加多个课节且教室不同，建议以这些课节可用容量的最小值作为该安排的可售上限。多个活动共用同一实际教学班级时，共享容量账目，不能每个商品各售一遍教室满额。

### F02 家长报名

提交后创建活动报名记录及相应订单或待支付记录，保留所选安排和来源。未缴清不占位，不产生本次报名的校区招生任务。

提交记录不等于已缴清、已成团、已占位或已推送。重复点击同一次提交不得重复创建记录；已有同一学生同一安排的有效报名时提示原记录，重新报名及历史取消后的重复购买细节按第十二章确认。

### F03 缴费与名额校验

缴费时重新检查安排是否有效及剩余名额。缴清确认与名额占用必须保持一致：未缴清不占位；缴清成功后占一个真实学生名额；拼团尚未成功也继续保留。

不采用提交订单即锁位、待付款长期占位或按团人数整体占位的方案。支付发起前可检查余量，但不能把一次前端查询当作保证；最后一个名额的并发支付必须在服务端处理。

线上支付回调已确认收款，但名额被其他订单占用时，必须如实记录资金结果并进入有明确提示的异常处置，不得静默超额入班或丢弃收款记录。建议采用关闭对应报名并按原支付退回的补偿路径，具体与支付系统联调确定。原型演示不能代替真实支付回调验证。

### F04 固定规格拼团

创建团时确定人数规格和每位成员的价格。进入二人团按二人团价格，进入三人团按三人团价格；一个团不能在人数增长后自动变为其他规格，也不对已有订单自动重定价。

每个真实成员分别报名、生成自己的订单并付款。推荐以已缴清且未取消的真实成员作为实际成团人数，计数粒度及一位家长多名子女的处理见第十二章。成员选择的校区和上课安排不限制加入同一个团。

### F05 拼团结束结算

| 到期或结束时的情况 | 处理结果 |
| --- | --- |
| 已达到目标人数 | 正常成团，不增加虚拟名额 |
| 人数不足且开启虚拟成团 | 按目标人数补足差额，记录为虚拟成团，真实订单价格不变 |
| 到期人数不足且关闭虚拟成团 | 标记拼团失败，取消相关交易并对已收款订单发起退款 |

虚拟成团记录真实人数与补位人数，不能伪造学生或已支付订单。未缴清的真实报名不能因虚拟成团自动变为已缴清或获得教学名额。

拼团失败时退款按成员订单分别处理，未支付订单无款可退。退款申请、处理中、成功、失败需要分开记录；退款失败保留待处理事项，不允许前端直接显示已退款。建议报名取消时释放对应名额，释放与资金退款分别记录且防止重复执行。

管理员提前结束售卖且虚拟成团开启时，按已确认的“活动到期或结束”规则结算。关闭虚拟成团时提前结束的处理，以及已成团后成员主动退团，不在到期失败规则中擅自推导，见第十二章。

### F06 运营手动推送校区

运营在活动报名列表选中记录并执行“推送校区”。系统按每条记录所选校区创建承接事项，记录批次、推送人、时间与结果。不同校区、不同课程安排的记录可在同一批次推送。

未缴清或未成团不能成为拒绝推送的理由。系统仍需验证记录存在、操作者有权操作、目标校区有效，以及是否已经推送；这类数据有效性检查不等于支付门槛。

报名源记录持续保留。重复推送或网络重试不得创建重复承接事项。建议批次按记录返回成功、已推送跳过、失败三类结果，不因一条异常隐藏其他记录的处理结果。

### F07 主管分配及顾问跟进

目标校区主管在活动报名招生页面按班级查看待分配记录，选择本校区有权限且在职的顾问。原顾问仅作为推荐，不自动完成分配。

分配后顾问收到关联本次报名的任务，能直接查看课程与上课安排，记录沟通并开展正价转化。两个主管同时分配同一记录时必须检测变更冲突，避免后一次操作无提示覆盖已分配结果。

本次报名的责任人不直接覆盖学生在其他校区或其他业务中的所有负责人。运营能够回看推送、分配和转化结果，但不因此获得正价沟通或任意更换校区顾问的权限。

### F08 多课节教学与考勤

报名关联所选安排及其课节清单。老师按授课关系、教务按服务关系进入名单，逐课节记录出席情况；顾问查看这些结果用于后续沟通。

教学与招生信息通过同一报名关联更新，无需重复录入学生。拼团虚拟补位不进入教学名单。对“未成团但已经开课”的情况不新增判断分支或专门工作流。

### F09 转交与报名变更方案

| 操作场景 | 建议实现 | 必须保持的一致性 |
| --- | --- | --- |
| 同校区仅换顾问 | 复用“转同事”，限定合法接收人并记录历史 | 报名校区、课表、订单和名额不变 |
| 同校区换时间或教学班级 | 独立“调整报名”，检查目标安排余量 | 课程时间与考勤名单同步，默认保留顾问 |
| 更换上课校区 | 调整报名安排，再交目标校区主管分配 | 不能只换负责人；原安排名额与新安排名额同步处理 |
| 取消报名 | 独立取消流程，记录名额、订单及退款状态 | 不删除来源与历史沟通，不取消学生其他报名 |

调整失败必须保留原有有效安排，不能出现原名额已释放而新安排未成功的半完成状态。跨校区变更原负责人访问范围、审批人及费用差额处理仍需按第十二章确认。

这些是基于现有“转同事”能力的扩展建议，不代表已确认所有调课、退费授权规则。

## 6 状态与数据一致性

### 6.1 状态分开保存

| 状态维度 | 建议状态 | 变化依据 |
| --- | --- | --- |
| 报名 | 已提交、已取消 | 家长提交或合法取消操作 |
| 缴费 | 未付款、部分付款、已缴清 | 真实收款明细及全部应缴金额 |
| 拼团 | 不适用、拼团中、正常成团、虚拟成团、失败 | 所选售卖方式、真实人数及结束结算 |
| 名额 | 未占位、已占位、已释放 | 缴清及名额检查、报名取消或变更 |
| 推送 | 未推送、已推送 | 运营手动推送成功；失败保留未推送并记录原因 |
| 分配 | 不适用、待分配、已分配 | 未推送时不适用；主管完成或调整分配 |
| 招生跟进 | 待首次联系、跟进中、正价待缴清、已转正价、已结束 | 顾问动作和正价订单缴清事件 |
| 考勤 | 每课节待考勤、出席、缺席及已有有效状态 | 对应课节的教学考勤记录 |
| 退款 | 无退款、待退款、退款中、已退款、退款失败 | 退款任务与真实支付渠道结果 |

以下组合都是有效业务状态，不能合并成一个“报名成功”开关：

- 未付款、拼团中、未占位，但已推送且已分配顾问。
- 已缴清、拼团中、已占位，但运营尚未推送。
- 已缴清、虚拟成团、已占位，实际学生人数仍小于团目标人数。
- 拼团失败、报名取消、名额已释放，但退款仍处理中；原推送与沟通历史继续保留。

### 6.2 必须保持的一致性

1. 活动订单缴清与真实名额占用对应，不能超出所选教室允许的人数。
2. 同一报名同一有效教学安排最多占一个名额，不能按课节数重复扣减同一班的学生席位。
3. 拼团真实人数、虚拟人数、教学学生人数分别计算，虚拟补位永远不产生收款或席位。
4. 推送不能增加学生档案副本，也不能直接跳过主管完成顾问分配。
5. 每次报名独立保留课程、时间、订单、团和顾问上下文；已有其他报名不被覆盖。
6. 取消、退款、改派和改班保留前后值及操作者，不以删除记录代替业务变更。
7. 重复支付回调、推送请求、结束结算和退款回调只产生一次有效业务结果。

## 7 数据模型与开发接口建议

### 7.1 关键对象

字段名是开发建议，具体命名可沿用项目规范，关系和隔离要求必须保留。

| 对象 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| 活动课 | activityCourseId、courseId、名称、运营负责人、发布状态 | 复用课程资料，关联多个可报名安排及售卖方案 |
| 可报名安排 | offeringId、activityCourseId、campusId、classId、教室关联、容量引用 | 用于将一次单选对应到确定教学安排，不作为新一级业务名 |
| 课节 | lessonId、offeringId、开始结束时间、roomId、teacherId | 一个安排包含一个或多个课节；复用既有排课对象时避免重复维护 |
| 售卖方案 | salePlanId、方式、期间、适用安排、virtualGroupEnabled、版本 | 直接价格或人数规格集合，修改不回改历史订单 |
| 拼团规格 | groupSpecId、targetSize、price | 一个团引用一种规格及其下单价格快照 |
| 拼团实例 | groupId、规格快照、状态、真实人数、虚拟人数、结算时间 | 团员关联各自报名与订单；不绑定单一校区或教学班级 |
| 活动报名 | registrationId、studentId、offeringId、salePlanId、groupId、source | 保留家长选择及必要快照；支付、名额、推送等状态分别关联 |
| 订单及收退款 | orderId、registrationId、应缴、收款流水、refundId、渠道状态 | 每位成员分别付款；金额与虚拟名额无关 |
| 名额记录 | reservationId、registrationId、offeringId、状态、获得释放时间 | 只记录真实占位；未缴清不创建有效占位 |
| 校区交接 | handoffId、registrationId、targetCampusId、推送批次及操作者 | 首次推送唯一，合法变更交接须保留版本与历史 |
| 招生任务 | taskId、registrationId、leadId、campusId、assigneeId、阶段 | 复用学生与线索主档；原顾问推荐值与实际分配值分开 |
| 课节考勤 | registrationId、lessonId、到课状态、操作者及时间 | 一条报名每个课节独立记录 |

教室容量是配置来源，容量引用及历史快照需能区分。教室改小到低于已占人数时，应提示冲突并进入人工调整，不得静默挤出已付款学生。沿用现有同教室同时间排课冲突规则，不能因活动商品不同就忽略冲突。

### 7.2 服务端业务操作

以下是操作职责，不代表当前已存在同名接口。

| 操作 | 输入重点 | 返回或事件 | 一致性要求 |
| --- | --- | --- | --- |
| 保存或发布活动课 | 课程、教学安排、售卖方案 | 配置版本及校验结果 | 校区教室匹配，课节完整，规格价格有效 |
| 提交报名 | 学生、单选安排、售卖方案、团、请求标识 | 报名及订单 | 不推送、不占位；防重复提交 |
| 确认缴费 | 订单、真实收款凭证或支付回调 | 缴清结果及名额状态 | 校验渠道真实性，避免重复入账及超售 |
| 批量推送 | 报名ID集合、筛选选择范围、请求标识 | 逐条结果及各校区汇总 | 服务端校验每条权限和状态，防重复交接 |
| 分配顾问 | 承接事项、顾问、当前数据版本 | 分配记录及顾问待办 | 校区范围匹配，防并发覆盖 |
| 结束拼团 | 团及售卖配置版本、触发原因 | 成团、虚拟补位或失败退款任务 | 可重试，不能重复补位或重复退款 |
| 变更报名安排 | 原报名、目标安排、原因及版本 | 变更记录、名额和交接变化 | 目标失败时保留原有效安排 |
| 记录考勤 | 课节、报名、状态 | 考勤结果 | 教学权限及课节归属一致 |

跨支付渠道和本地数据的更新采用可重试事件与补偿任务，不能假设外部收款、数据库更新、退款能在一个事务中全部完成。需要记录异常任务、最后一次执行结果和重试次数，并能对账。

## 8 权限与部门分工

| 岗位 | 数据范围 | 主要动作 | 约束 |
| --- | --- | --- | --- |
| 运营专员 | 授权负责的活动课及来源报名 | 建课或维护、查看报名、多选全选、推送校区、查看结果 | 不因来源关系获得正价跟进或校区任意改派权限 |
| 运营主管 | 授权运营团队及活动范围 | 管理活动售卖、查看团队报名与推送结果 | 不默认拥有财务退款权限 |
| 校区主管 | 明确授权校区内已推送报名 | 按班级查看、分配及调整本校区顾问 | 不分配其他校区报名，不自动取得其他团员信息 |
| 招生顾问 | 已分配给本人的本次报名任务 | 查看必要报名及课表信息、沟通、邀约、正价转化 | 列表分组和统计仅含本人有权记录 |
| 教师及教务 | 本人授课或服务关系覆盖的教学安排 | 课表、学生名单、逐课节考勤和服务 | 不因团员关系扩展到其他校区学生 |
| 财务 | 授权范围内的订单与收退款 | 收款确认、退款处理、异常对账 | 不修改团规格价格或招生归属来调整业绩 |
| 管理员 | 明确授予的配置和管理范围 | 基础资料、授权、审计与异常协助 | 敏感财务动作单独授权 |

来源查看权、学生档案查看权、跟进操作权、完整联系电话、金额查看、导出和退款权限分别校验。页面、搜索、统计、详情及服务端操作使用一致的数据范围。

多人跨校区参团不构成跨校区查看整团所有学生联系方式的授权。校区员工看到本校区任务及必要团状态，团内其他家长的私人信息不自动开放。

运营团队内部查看范围和报名变更审批规则沿用现有授权作为开发默认，扩展范围需按第十二章确认。

## 9 统计与审计

### 9.1 分开呈现各阶段指标

活动列表及报表至少分开展示：真实报名记录数、去重学生数、已缴清数、已占位数、真实已成团数、虚拟成团团数、已推送数、已分配数、课节到课情况、正价转化结果和退款金额。

拼团人数不作为教学人数，虚拟补位不作为真实获客、报名、收入或正价转化。多课节出席人次不能直接作为活动去重到课人数。活动费缴清不能触发正价课成交业绩。

“有效报名”是否还需满足成团条件，以及取消退款后运营绩效是否扣回，本轮未最终确认。开发先保留可核验的各阶段事实，不把一个混合成功指标直接用于正式绩效。

### 9.2 审计记录

记录活动及价格版本变更、报名提交、收款及退款、名额获得释放、正常或虚拟成团、每次推送、顾问分配调整、教学安排变更及考勤修改。日志包含业务对象、操作者、时间、前后值和操作原因；自动结算记录触发来源。

已推送报名取消或退款后，在运营和招生页面同步展示最新状态，保留历史交接及沟通。建议不自动删除线索，由有权限人员决定是否继续跟进其他课程。

以下为原版源文件中的已核对能力，不表示各Demo副本都已实现本文件需求。开发前应明确实际目标目录，不能同时修改原版、demo-v2、demo-v3。

### 10.2 推荐交付顺序

| 阶段 | 开发内容 | 交付条件 |
| --- | --- | --- |
| P0 第一阶段 | 数据关系、活动课及课节配置、教室容量、直接售卖、报名与缴费名额校验 | 单次和多次课程均可报名，最后一个名额不会超售 |
| P0 第二阶段 | 多规格拼团、分别付款、跨校区参团、虚拟成团、失败退款与重试 | 团、订单、名额状态互相一致且可追溯 |
| P0 第三阶段 | 报名总表、批量推送、主管分配、原顾问推荐、按班级跟进及权限 | 未缴清可推送，未推送不自动进入招生任务，顾问能看到完整报名上下文 |
| P0 第四阶段 | 逐课节考勤、状态回传、审计及核心验收 | 教学与招生共享同一报名事实，各岗位数据范围正确 |
| P1 | 复杂调课转校、批量异常处理、指标深度分析 | 在变更授权、费用差额和绩效口径确定后交付 |

已有“转同事”入口保留；不能在复杂联动未完成时把它宣传为支持换校区、换课或取消报名。阶段仅表示依赖顺序，不承诺具体开发工期。

### 10.3 历史数据迁移

已有课程及班级关联到活动课和具体教学安排，保留学生ID、来源、原订单、顾问和校区。缺少课节明细或教室关联的历史报名进入待核对列表，不能按同名课程自动猜测。

已缴清未成团报名应补齐真实占位；已推送记录保留交接事实，不因旧版曾要求缴清而重新推送。用历史单次“已到课”数据不能推断多课节均出席。

上线切换前核对报名数、已缴清金额、已退款金额、已占名额、待分配任务和顾问责任关系，并准备迁移回退方案。

| AT22 | 活动费缴清但尚未报名正价课 | 不计正价转化成功；虚拟名额不计真实报名和收入 | BR19、第九章 |
| AT23 | 未推送报名后续缴清或成团 | 支付及团状态更新，但仍不自动推送校区 | BR13、F03至F06 |
| AT24 | 仅执行转同事 | 改变本次跟进责任并留痕，不擅自改报名校区、课表及订单 | F09 |

P1补充验收：换安排先检查目标名额；失败保留原安排；跨校区交给目标主管；费用、退款、历史考勤和访问范围按最终确认方案同步处理。

## 12 待确认细节与建议默认

以下事项不推翻第二章已确认规则，不需要重新讨论“未缴清能否推送”“团员能否跨校区”等已定事项。

| 编号 | 待确认事项 | 建议与影响 |
| --- | --- | --- |
| D01 | 真实成团人数的计数粒度，以及一名家长为多名子女报名的处理 | 建议以已缴清且有效的学生报名为单位，同一学生在同一团去重；影响成团判定，不影响各自付款原则 |
| D02 | 关闭虚拟成团时提前结束售卖，以及已成团后个别成员主动取消 | 到期失败退款已确定；其他情形需明确是否保留其余成员团价、是否重新判断成团，不得自动套用整团取消 |
| D03 | 调课、转校、取消报名的授权人、费用差额及退款审批 | 建议复用现有授权；跨校区目标主管接手，交易及教学安排同步变更；复杂分支纳入P1 |
| D04 | 有效报名绩效是否要求成团、退款后是否扣回及归属周期 | 先分开呈现报名、缴清、成团、退款事实，确认后再形成绩效指标 |
| D05 | 重复报名边界、历史取消后重新报名以及多个原顾问时的推荐顺序 | 建议同一学生同一有效安排防重复；多个同校区候选顾问时展示候选及历史，由主管选择 |

技术联调需补齐支付已到账但名额不足的补偿路径、退款重试及对账。未付不占位仍是确定规则，不能以处理并发为由改回提交订单即长期锁位。

## 13 实施变更对照

| 需替换或避免的设计 | 目标规则 |
| --- | --- |
| 付费活动缴清后才能向校区提交 | 允许运营主动推送未缴清、未成团报名 |
| 报名自动进入校区队列 | 不自动进入；必须由运营多选或全选后推送 |
| 仅按学生列表承接活动报名 | 增加按活动课及班级组织的招生视图，详情保留完整报名信息 |
| 把对外课程名称改成活动班 | 保持活动课，课程下含多个课节；原有班级能力用于组织学生 |
| 活动到课只有一次性标记 | 改为按课节考勤 |
| 按最终人数自动变化价格 | 二人团、三人团分别锁定固定人数规格和价格 |
| 要求团员同校区同时间上课 | 团与教学分开，可跨校区、跨时间参团 |
| 未付款限时占位 | 不采用；未缴清不预留，缴费时重新校验 |
| 用转同事处理所有报名变化 | 仅复用责任交接；课表、名额、订单和跨校区接手需单独联动 |

## 14 开发完成定义

活动课在独立入口完成课程、教学安排和售卖设置；家长报名关联真实订单和教室名额；运营能按记录批量推送；校区主管能按班级分配；顾问能直接看到报名上下文；教学能按课节考勤。所有页面展示同一组关联事实，避免重复录入和状态互相覆盖。

P0验收全部通过，支付及退款异常可追溯，数据权限覆盖服务端与批量操作，才算具备正式交付条件。P1和待确认项不能在未实现时通过隐藏按钮或文字说明宣称已支持。
